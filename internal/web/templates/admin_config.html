Discovery & cache

Changes to discovery take effect on the next discovery cycle / restart. Metrics poll picks up new backends within poll_interval.

Metrics & scoring

Lane/queue/pressure weights only apply to NInfer engines reporting /slots + /usage — that's the specialized fork. Other engines fall back to a vLLM-metrics heuristic (see README "Engine metrics").

Costs & hosts

One entry per physical box. GPU energy comes from the engines' NVML; overhead watts and capex drive the full-cost view at /admin/costs.

Model pools

One pool = one virtual model id that load-balances across several GPUs. Members are picked per request by load score; big prompts prefer large-ctx members.

Pool MEMBER model ids are hidden from /v1/models; the pool name is what clients call.

Overflow pairs

Route requests away from a saturated model to a fallback engine (failover happens before any bytes reach the client).
